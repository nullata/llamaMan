# Устранение неполадок

Полная таблица «симптом → решение». В [README](../../README.md#troubleshooting) остаются девять самых частых строк первого запуска; всё остальное — здесь.

| Симптом | Решение |
|---|---|
| Инстанс завис на **starting** | Проверьте логи через кнопку Logs. Частое: OOM, опечатка в пути модели, повреждённый GGUF, образ не скачан |
| _"Docker image not found"_ | Скачайте подходящий образ: `docker pull ghcr.io/ggml-org/llama.cpp:server-cuda` (или `server-rocm` / `server-sycl` / `server`) |
| _"Docker API error"_ при запуске | Убедитесь, что `/var/run/docker.sock` смонтирован (по умолчанию в `docker-compose.yml`) |
| Нет GPU / ошибка CUDA | Убедитесь, что NVIDIA Container Toolkit установлен и `docker run --gpus all` работает на хосте |
| Нет GPU / ошибка ROCm | Убедитесь, что `/dev/kfd` и `/dev/dri` существуют и ваш пользователь состоит в группах `video`/`render` |
| Нет GPU / ошибка Intel Arc | Убедитесь, что `/dev/dri` доступен и ваш пользователь состоит в группах `video`/`render` |
| Vulkan-образ падает с _"Unable to find group render"_ | Установите `GPU_TYPE=vulkan`, чтобы llamaMan подключал GID групп render/video хоста по числовым значениям (основанное на именах group_add не работает на образах, у которых в /etc/group нет записи `render`) |
| Статистика GPU недоступна | NVIDIA: раскомментируйте блок `deploy.resources.reservations`. AMD/Intel: убедитесь, что `/sys/class/drm:ro` смонтирован |
| Определён неверный производитель GPU | Установите `GPU_TYPE=cuda`/`rocm`/`intel` для переопределения |
| Инстанс завис на **starting** при bare-metal запуске | Контейнер здоров, но llamaman до него не достаёт. Явно задайте `LLAMAMAN_IN_DOCKER=false`/`true`, если автоопределение неверно для вашей среды |
| Strata: _"Docker image 'strata:latest' not found"_ | Скачайте или соберите образ Strata в Settings → Docker Images (или `docker build -t strata .` в клоне репозитория Strata). См. [Strata](STRATA.md) |
| Модели Strata не отображаются в списке | Установите `STRATA_ENABLED=true`; узел должен быть NVIDIA (`GPU_TYPE=cuda`, если определение не сработало). `GET /api/engines` показывает причину |
| Инстанс Strata завис на **starting** | Нормально в течение нескольких минут при первом запуске (загрузка + pack). Карточка показывает стадию; лог показывает setup Strata. "setup failed" означает, что его setup остановился — прочитайте строку с `[X]` в логе |
| Модальное окно статистики пустое | Включите **Settings → App Settings → Request recording** (см. [Запись запросов и статистика](CONFIGURATION.md#request-recording--stats)) |
| Запуск падает с ошибкой GPU/CDI на хосте без проброса GPU | Установите **GPU Layers** в `0` для режима только CPU без подключения устройства GPU, или почините GPU-рантайм |
| Конфликт портов | Форма автоматически предлагает свободный порт; скорректируйте при необходимости |
| Модель не отображается в OpenWebUI | Убедитесь, что `OLLAMA_BASE_URL=http://llamaman:42069`. Проверьте, что `/api/tags` возвращает модели |
| OpenWebUI получает 401 | `require_auth` включён (по умолчанию). Создайте API-ключ и задайте `OPENAI_API_KEYS` в OpenWebUI |
| OpenAI-клиент получает 503 при заполненных моделях | Достигнут лимит `LLAMAMAN_MAX_MODELS`, а OpenAI API по умолчанию не может никого вытеснять. Поднимите лимит или включите переключатели вытеснения: [Вытеснение моделей](MODELS.md#model-eviction) |
| Контейнеры не убираются после остановки | llamaMan удаляет контейнеры при остановке. Осиротевшие после падения: `docker ps --filter name=llamaman-`, или перезапустите llamaMan (усыновление осиротевших работает при старте) |
| Клиент (Hermes / OpenWebUI / и т. п.) сообщает обученное контекстное окно вместо лимита из пресета | Обновитесь до 1.1.2+. `/api/ps` теперь включает `context_length`, равный рантайм-контексту, с которым запущен инстанс, а `model_info["<arch>.context_length"]` в `/api/show` переопределяется эффективным лимитом |
| Клиент, спрашивающий имя группы очереди, получает свой дефолтный ctx (например, 128k) вместо реального контекста развёртывания | `/api/show` и `/v1/models` теперь отвечают для группы очереди на любом кластеризованном узле — даже на том, у кого нет локального члена группы — используя рантайм-ctx пиров из общего состояния. Группы с несколькими членами сообщают минимум по живым членам, чтобы рекламируемое значение было безопасно для любой цели диспетчеризации. См. [Clustering](CLUSTERING.md) |
