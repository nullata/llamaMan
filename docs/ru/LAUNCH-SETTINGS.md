<a id="launch-form-tools"></a>
## Инструменты формы запуска

Ряд действий формы запуска несёт три кнопки-инструмента справа:

- **Export preset** — скачать текущие значения формы как JSON-файл (переносимо между узлами; в хранилище не сохраняет).
- **Import preset** — загрузить preset JSON в форму. Заполняет только поля; чтобы сохранить, всё равно жмите Save Preset.
- **Copy llama.cpp command** — копирует в буфер эквивалентный вызов `llama-server ...` для текущих значений формы. Рендерится на сервере тем же кодом выпуска флагов, что и настоящий запуск, поэтому синхронен по мере эволюции флагов.

При свёрнутых настройках кнопка **Quick Launch** запускает выбранную модель прямо из её пресета.

Каждый инстанс даёт OpenAI-совместимый API на назначенном порту. Когда выбран GGUF, llamaMan читает его метаданные, определяет число слоёв и показывает его рядом с **GPU Layers** (например `/ 32`).

**Model Settings**

|---|---|---|---|
| **Context Size** | `4096` | `--ctx-size` | Потолок токенов промпта + ответа на запрос |
| **Parallel Slots** | `1` | `--parallel` | Параллельные слоты декодирования внутри llama-server (KV-слоты) |
| **Batch Size** | `2048` | `--batch-size` | Максимум токенов промпта, обрабатываемых за один шаг. Пусто — флаг не выпускается |
| **Micro-batch Size** | `512` | `--ubatch-size` | Физический батч, отправляемый на GPU; больше = быстрее prefill, больше VRAM. Embedding-модели и decision-модели с энкодером (BERT-стиля) требуют весь свой вход в одном микро-батче. Пусто — флаг не выпускается |
| **K Cache Type** | `f16` | `--cache-type-k` | `f16`/`f32`/`bf16`/`q8_0`/`q5_1`/`q5_0`/`iq4_nl`/`q4_1`/`q4_0`. Квантование уменьшает память K; работает с Flash Attention и без |
| **V Cache Type** | `f16` | `--cache-type-v` | Те же значения. Любое квантованное значение **требует Flash Attention = On** — UI делает дропдаун неактивным и автоматически возвращает V в `f16`, когда FA уходит с On |
| **Flash Attention** | `auto` | `--flash-attn on\|off\|auto` | `auto` не выпускает флаг (собственный дефолт llama.cpp); `on` принудительно (падает, если бэкенд не может); `off` отключает |
| **Reasoning Format** | `auto` | `--reasoning-format` | `none` / `auto` / `deepseek` / `deepseek-legacy`. Управляет разбором thinking-тегов (уводятся в `reasoning_content` или остаются инлайн). `auto` не выпускает флаг |
| **Load Mode** | `auto` | `--load-mode` | `auto` / `none` / `mmap` / `mlock` / `mmap+mlock` / `dio`. Как веса модели загружаются в память (преемник устаревших `--mlock`/`--mmap`/`--direct-io`). `auto` = mmap, если он поддерживается; совпадает с дефолтом llama.cpp и не выпускает флаг |

**Container & Proxy Settings**

| Настройка | По умолчанию | Флаг | Заметки |
|---|---|---|---|
| **Port** | *(авто)* | - | Публичный порт; должен попадать в `PORT_RANGE_START/END` |
| **CPU Threads** | *(авто)* | `--threads` | Также ставит контейнеру CPU-квоту (`--cpus N`). Пусто = пусть контейнер и llama-server используют все ядра |
| **CPU Threads Batch** | *(= CPU Threads)* | `--threads-batch` | Отдельное число потоков для prefill/batch. Пусто в llama-server откатывается на `--threads` |

| **Max Concurrent** | `0` | - | Максимум запросов инференса в полёте; лишние встают в очередь. `0` = без гейта. См. [Параллелизм и очереди](#concurrency--queueing) |

**GPU Settings**

| Настройка | По умолчанию | Флаг | Заметки |
|---|---|---|---|
| **GPU Layers** | `-1` | `--n-gpu-layers` / `--gpu-layers` / `-ngl` (алиасы) | `-1` = **auto** (llama.cpp оценивает VRAM и выбирает; могут остаться слои на CPU). `-2` = **all** (принудительно все слои; падает, если не влезает). `0` = только CPU, GPU к контейнеру не подключается. Любое положительное N выгружает на GPU ровно N слоёв, начиная снизу |
| **MoE CPU Layers** | `0` | `--cpu-moe` / `--n-cpu-moe` | Осмысленно только на Mixture-of-Experts моделях. `0` = ничего не выпускать. `-1` = `--cpu-moe` (веса маршрутизированных экспертов всех слоёв закреплены на CPU). Положительное N = `--n-cpu-moe N` (эксперты первых N слоёв на CPU). Сжимает VRAM в ~4-10 раз на больших MoE, потому что эксперты доминируют в числе весов, но на токен срабатывают лишь несколько. На плотных моделях безвредно: регулярка llama.cpp (`\.ffn_(up\|down\|gate\|gate_up)_(ch\|)exps`) ни во что не попадает, и переопределение молча отбрасывается. **Не покрывает общих экспертов** (`_shexp` в DeepSeek-MoE / Qwen2-MoE / Hunyuan-MoE) — для них добавьте override `-ot` в Extra Args |
| **GPU Devices** | *(все)* | *(уровень контейнера)* | Перечисленные через запятую индексы хост-GPU для подключения (например `0,1`). Внутри контейнера перенумеровываются с 0. Не поддерживается на Intel Arc |
| **Split Mode** | `layer` | `--split-mode` | `none` (один GPU, Tensor Split игнорируется) / `layer` (дефолт llama.cpp; делит целые слои) / `row` (делит строки тензоров; обычно выигрывает только с быстрым интерконнектом вроде NVLink) |
| **Tensor Split** | *(авто)* | `--tensor-split` | Перечисленные через запятую относительные веса на видимый контейнеру GPU (например `24,16`). Пусто автозаполняется из полного VRAM каждого GPU при запуске. Игнорируется при Split Mode = `none` или одном видимом GPU |

<a id="live-preset-updates"></a>
## Живое обновление пресетов

Сохранение пресета на лету обновляет уже запущенные инстансы этой модели там, где возможно:

- **Живо (без перезапуска):** `idle_timeout_min`, `max_concurrent`, `max_queue_depth`, `share_queue`, все шесть полей прокси-сэмплинга, все пять полей loop-detection (следующий запрос их подхватит)
- **Требуют перезапуска:** всё, запечённое в контейнер при запуске (gpu layers, MoE CPU layers, ctx size, threads, threads-batch, cache types, flash-attn, reasoning-format, load-mode, DRY sampler, поля spec-decoding, флаг embedding, поля mmproj/PDF, extra args, memory limit)

**Оговорка про прокси-сэмплинг:** если инстанс запущен с `idle_timeout=0`, `max_concurrent=0` и `override_enabled=false` одновременно, sidecar-прокси не порождался. Живое переключение `override_enabled=true` тогда всё равно применяет переопределения на запросах, идущих через compat-эндпоинты приложения, но прямые попадания на публичный порт его обходят. В этом случае перезапустите инстанс, чтобы прокси был порождён.

<a id="concurrency--queueing"></a>
## Параллелизм и очереди

Когда **Max Concurrent** > 0, llamaMan ставит перед инстансом FIFO-гейт. Лишние запросы ждут до **Max Queue Depth**, затем отдают HTTP 429. Статистика гейта (активные + в очереди) видна через API.

**Parallel vs Max Concurrent:** `Parallel` управляет внутренними KV-слотами llama-server; `Max Concurrent` ограничивает, сколько запросов llamaMan пересылает одновременно. Используйте оба вместе (например `Parallel=4`, `Max Concurrent=4`), чтобы держать сервер сытым, не переполняя его слоты.

<a id="image--pdf-input"></a>
## Ввод изображений и PDF

Включите переключатель **Image & PDF Input**, чтобы загрузить мультимодальный проектор (`--mmproj`) визуальной модели вместе с основным GGUF. Поле **MMPROJ Model** принимает проекторный GGUF (типичное имя файла: `mmproj-<model>-<precision>.gguf`).

**Offload mmproj to GPU** (по умолчанию вкл): llama.cpp держит проектор на GPU, пока ему не дадут `--no-mmproj-offload`, поэтому *on* вообще не выпускает флаг (побайтово идентичный CLI тому, что был до появления этой опции), а *off* передаёт `--no-mmproj-offload`, чтобы гонять vision-энкодер на CPU — полезно на тесных VRAM-конфигурациях, где энкодер закрепляет несколько ГБ.

**PDF** поддерживаются растеризацией каждой страницы в PNG **до** пересылки в llama-server (у которого нативной PDF-поддержки нет). Включите **Accept PDF uploads** (внутри группы Image & PDF Input), чтобы включить это для инстанса; главный переключатель **Image & PDF Input** управляет всей группой — выключение также снимает PDF-подпереключатели, поскольку у растеризованных страниц нет vision-модели, до которой можно дотянуться без проектора. Распознаются в обоих:

- **OpenAI**: `image_url` с URL `data:application/pdf;base64,...` или более новый блок `file`
- **Ollama**: base64-байты PDF, подмешанные в `images[]` — llamaMan распознаёт сигнатуру `%PDF-` и разворачивает PDF; обычные изображения идут существующим путём

**Быстрый путь через текстовый слой** (по умолчанию выкл): с включённым **Try text layer first** llamaMan запускает `pypdf.extract_text()` перед растеризацией. Изначально цифровые PDF (Word/LaTeX/печать из браузера) с содержательным текстом (≥ ~50 знаков/стр.) вставляются инлайн одним текстовым блоком и полностью пропускают vision-путь. Разрежённый текст откатывается на растеризацию. По умолчанию выкл, потому что растеризация сохраняет вёрстку для vision-модели, а предсказуемое поведение на каждом PDF лучше незаметного быстрого пути.

**Потолки на запрос:** `PDF DPI` (72-600, по умолчанию 200) и `Max PDF Pages` (1-200, по умолчанию 20). PDF сверх потолка отдают HTTP 400 вместо обрезания.

**Параллельность растеризации:** рендеринг PDF тяжёл по CPU и RAM и идёт в потоке воркера gunicorn до любого per-instance гейта. Общепроцессный семафор ограничивает одновременные растеризации; настраивается через `LLAMAMAN_PDF_MAX_CONCURRENT` (по умолчанию 4).

## Anti-Loop

Два независимых переключателя в секции **Anti-Loop** формы запуска, оба по умолчанию выкл. Они бьют в одну проблему (модели, застревающие в устойчивых циклах вывода) в двух разных точках конвейера; для лучшего покрытия используйте оба вместе.

**DRY sampler (мягкий, на этапе sampling).** Отображается в `--dry-multiplier` / `--dry-base` / `--dry-allowed-length` / `--dry-penalty-last-n` llama-server. Каждому токену, который продолжил бы недавно виденный n-gram, при sampling начисляется вероятностный штраф, так что модель уводится от повторения себя ещё до того, как выплюнет дублирующийся фрагмент. Это *мягкая* линия обороны — обычно для прозы достаточно одной её. Запекается при запуске контейнера; правка пресета требует перезапуска. Multiplier = 0 полностью отключает (собственный дефолт llama.cpp).

*DRY Sampler* (запекается при запуске — требует перезапуска):

| Настройка | По умолчанию | Флаг | Заметки |
|---|---|---|---|
| Multiplier | `0.8` (значение UI; `0` отключает) | `--dry-multiplier` | Сила штрафа; llama.cpp трактует `0` как отключено |
| Base | `1.75` | `--dry-base` | Экспоненциальное основание ≥ 1.0 |
| Allowed Length | `2` | `--dry-allowed-length` | N-grams длиной до этой — исключение |
| Penalty Last N | *(авто)* | `--dry-penalty-last-n` | Окно ретроспективы. Пусто не выпускает флаг |

**Output loop detection (жёсткий, постфактум).** Когда DRY не хватает — модель всё равно застревает в устойчивом аттракторе — прокси llamaman следит за видимым текстом ответа ассистента (content + reasoning), пока он стримится клиенту. С каждым циклом сканирования (по умолчанию: инлайн каждые 64 чанка, плюс фоновый воркер-запасной на 10 с) последние `min_chunk_chars` буфера проверяются на повторение. Если они встречаются ≥ `min_repetitions` раз, ход завершается:

- **Исходящее соединение к llama-server закрывается** — stop-on-client-disconnect у llama-server останавливает генерацию, освобождая модель следующему запросу.
- **В поток клиента инжектируется синтетический терминатор** — OpenAI-клиенты видят финальный delta с `finish_reason=stop` и содержимым `[llamaman: output loop detected, ending turn]`; Ollama-клиенты видят `done_reason: "loop_detected"` на строке `done: true`.

*Output Loop Detection* (на стороне прокси; обновляется из пресета живо — следующий запрос подхватит новые пороги):

| Настройка | По умолчанию | Заметки |
|---|---|---|
| Min chunk chars | `200` | Диапазон 60-4096. Ниже ловит более короткие циклы, но даёт ложные срабатывания на повторительно-легитимном контенте |
| Min repetitions | `3` | Диапазон 2-20 |
| Buffer size (chars) | `8192` | Скользящее окно на запрос в полёте. Диапазон 512-65536 |
| Scan every N chunks | `64` | Периодичность инлайн-сканирования |
| Fallback scan (seconds) | `10` | Фоновый воркер для стримов, которые выдают токены слишком медленно, чтобы попасть на инлайн-порог |

**Где следит:**
- **Compat-маршруты на `:42069`** (Ollama `/api/chat`, `/api/generate`; OpenAI `/v1/chat/completions`, `/v1/completions`) — всегда, когда переключатель включён для пресета целевого инстанса.
- **Порты инстансов (`8000-8020`)** — только когда sidecar-прокси для этого инстанса уже есть (т.е. также включены Idle Timeout, Max Concurrent или Proxy Sampling Overrides). Loop detection сам по себе sidecar-прокси не порождает — включите один из других трёх, чтобы следить и за прямыми попаданиями.

**Настройка:**
- `min_chunk_chars` (60-4096, по умолчанию 200) — наименьший повторяющийся период, который сработает. Меньшие значения ловят более короткие циклы, но рискуют ложными срабатываниями на повторительно-легитимном контенте (нумерованные списки, припевы стихов, markdown-таблицы). 60-100 — агрессивно; 200 — сбалансированный дефолт для прозы; 400+ срабатывает только на циклах размера абзаца.
- `min_repetitions` (2-20, по умолчанию 3) — сколько точных копий чанка должно появиться до завершения. 2 срабатывает на любой удвоенный чанк (агрессивно); 3-5 балансируют отзывчивость против ложных срабатываний.
- `max_buffer_chars` (512-65536, по умолчанию 8192) — скользящее окно на активный запрос. Должно быть не меньше `min_chunk_chars × min_repetitions`.
- `scan_every_n_tokens` (8-4096, по умолчанию 64) — периодичность инлайн-сканирования. Ниже = быстрее убьёт, больше CPU.
- `scan_interval_s` (1-600, по умолчанию 10) — как часто фоновый воркер пересканирует буферы, не попавшие на инлайн-порог.

Изменения порогов loop-detection вступают в силу на *следующем* запросе (стримы в полёте держат пороги, снятые при attach). Правки DRY требуют перезапуска, поскольку флаги запечены в контейнер.

**Алгоритм детекции** (v1): взять последние `min_chunk_chars` буфера как цель; считать точные вхождения; флаг при ≥ `min_repetitions`. Не ловит дрейфующие почти-повторы ("The answer is: The answer is: The answer is:" с лёгким дрейфом пунктуации между повторами) — те ловят защитные механизмы DRY на этапе sampling. Намеренно простой и дешёвый.

**Защитный инвариант:** каждый хук на streaming-пути обёрнут в `try/except Exception`, который логирует и проваливается дальше — баг детектора никогда не сломает стрим реального пользователя.

<a id="per-instance-proxy"></a>
## Прокси на инстанс

Когда для инстанса включены **Idle Timeout**, **Max Concurrent** или **Proxy Sampling Overrides**, llamaMan вставляет WSGI-прокси перед контейнером llama-server: публичный порт (например 8000) — это прокси; llama-server слушает отдельный внутренний порт. Прокси делает валидацию имени модели, wake-on-request для спящих инстансов, ограничение параллелизма `RequestGate` и инжекцию sampling.

**Валидация имени модели:** на инференс-эндпоинтах, если тело запроса имеет поле `"model"`, оно сравнивается с основой имени файла загруженной модели (в нижнем регистре, без расширения). **Префиксное совпадение принимается** (например `"qwen2.5-0.5b-instruct-q2"` совпадает с `"qwen2.5-0.5b-instruct-q2_k"`). Несовпадение отдаёт HTTP 404; для спящих инстансов — без пробуждения. Запросы без поля `"model"` пересылаются безусловно.

<a id="idle-timeout"></a>
## Тайм-аут простоя (Idle Timeout)

Задайте **Idle Timeout min** в форме запуска (0 = отключено). Когда включено, после N минут без запросов контейнер llama-server останавливается, освобождая VRAM; следующий запрос будит новый контейнер с той же конфигурацией. Клиенты видят тот же порт с задержкой холодного старта.

Для управляемых через прокси (OpenWebUI) инстансов используйте вместо этого `LLAMAMAN_IDLE_TIMEOUT`.
