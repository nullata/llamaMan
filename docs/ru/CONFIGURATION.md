<a id="running-bare-metal"></a>
## Запуск на bare-metal

Полезно для разработки или хостов (например WSL), где запуск самого менеджера в Docker неудобен. llama-server по-прежнему работает в контейнерах.

```bash
pip install -r requirements.txt
MODELS_DIR=./models DATA_DIR=./data LOGS_DIR=./logs \
  LLAMAMAN_NODE_NAME=dev python app.py
# or under gunicorn:
MODELS_DIR=./models DATA_DIR=./data LOGS_DIR=./logs \
  LLAMAMAN_NODE_NAME=dev gunicorn -c gunicorn.conf.py app:app
```

Один процесс под gunicorn обслуживает UI/API на `:5000` и прокси на `:42069` (`python app.py` без gunicorn поднимает dev-сервер Flask только на `:5000`). Контейнерный-vs-bare-metal определяется автоматически; если определение когда-нибудь ошибётся для вашего рантайма, явно задайте `LLAMAMAN_IN_DOCKER=true` или `false`.

<a id="authentication-detail"></a>
## Подробнее об аутентификации

Два типа учётных данных:

- **Сессионные cookie** для UI (создаются через `/setup` при первом запуске)
- **API-ключи** для внешних клиентов (`Authorization: Bearer llm-xxxxxxxxxx`), управляются в **API Keys** в UI

Переключатель **"Require authentication for all endpoints"** (по умолчанию включён) определяет, требуют ли эндпоинты обслуживания моделей bearer-токен:

| Переключатель | Эндпоинты моделей (`/api/chat`, `/v1/chat/completions`, порты инстансов) | Управленческие эндпоинты (`/api/instances` и т.д.) |
|--------|--------------------------------------------------------------------------|-----------------------------------------------|
| **ON** (по умолчанию) | Bearer-токен обязателен | Bearer-токен или сессия |
| **OFF** | Открыто | Bearer-токен или сессия |

Все три портовые поверхности (5000, 42069, 8000-8020) проходят через один и тот же auth-хук.

<a id="gpu-stats"></a>
## Статистика GPU

VRAM и утилизация по каждому GPU, запрашиваются нативно — работающий llama-server не требуется.

| Вендор | Метод | Требование |
|---|---|---|
| NVIDIA | `nvidia-ml-py` (напрямую NVML) | Раскомментируйте `deploy.resources.reservations` в `docker-compose.yml` ради capability `utility` тулкита NVIDIA |
| AMD | sysfs `/sys/class/drm` | Монтирование тома `/sys/class/drm:ro` (включено по умолчанию) |
| Intel Arc | sysfs `/sys/class/drm` | То же монтирование, что у AMD |

Без нативного доступа llamaMan откатывается к exec `nvidia-smi` / `rocm-smi` внутри работающего контейнера. Статистика всегда отражает полное состояние GPU хоста.

<a id="request-recording--stats"></a>
## Запись запросов и статистика

В **Settings → App Settings → Request recording**: **Off** (по умолчанию) / **Per request** / **Per conversation** (ходы группируются по хэшу содержимого системного промпта + первого пользовательского сообщения). Каждая запись ловит тела + поля конверта (модель, эндпоинт, статус, длительность, счётчики токенов) плюс **точные метрики по ходу** (пропускная способность, измеренная по окну генерации; TTFT). Записи лежат в `RECORDINGS_DIR` (JSON) или в таблице `request_log` (MariaDB). **Retention (days)** чистит ежечасно (`0` = хранить вечно).

Каждая карточка инстанса даёт кнопку **Stats** (число запросов, средняя/пиковая пропускная способность, средний TTFT/задержка, итоги по токенам, активный промежуток времени), свёрнутую из request log — поэтому она переживает остановку инстанса и показывает пустое состояние, когда запись выключена. Ссылка **Logging** в шапке открывает полноэкранный дашборд (плитки сводки, недавние беседы, drill-down по беседе) с выбором окна 24h / 7d / 30d / All time и фильтрами по модели и по дню над списком бесед.

<a id="storage-backends"></a>
## Бэкенды хранения

### JSON (по умолчанию)

Ноль настройки. Файлы в `DATA_DIR` (`/data`): `state.json`, `presets.json`, `users.json`, `settings.json`, `api_keys.json`, `request_log/`. Логи инстансов и загрузок идут в `LOGS_DIR` (`/tmp/llama-logs`).

### MariaDB / MySQL

```sql
CREATE DATABASE llamaman CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'llamaman'@'%' IDENTIFIED BY 'yourpassword';
GRANT ALL PRIVILEGES ON llamaman.* TO 'llamaman'@'%';
```

```yaml
environment:
  - DATABASE_URL=mysql+pymysql://llamaman:yourpassword@host:3306/llamaman
```

Таблицы автосоздаются при первом подключении. Логи запросов идут в таблицу `request_log` вместо JSON-каталога `request_log/` (`RECORDINGS_DIR` с MariaDB не действует).

Метаданные моделей по узлам (исходный репозиторий + хэш содержимого) живут в таблице `model_files` с областью «узел», с ключом `(node_id, model_path)`. При апгрейде каждый узел копирует свои записи из легаси-общего блоба настроек (только пути, которые существуют на его собственном диске) и сохраняет блоб как fallback для чтений и путь отката. Миграции версионируются по узлам.

> **Замечание про InnoDB:** `(node_id, model_path)` занимает `(64 + 700) × 4 = 3056` байт при utf8mb4, чуть ниже лимита индексов InnoDB в 3072 байта, поэтому таблица создаётся с `ROW_FORMAT=DYNAMIC`.

MariaDB — также предпосылка для [Clustering](CLUSTERING.md) и [Knowledge Base](KNOWLEDGE-BASE.md).

<a id="surviving-a-database-outage-local-mirror"></a>
## Работа при недоступности БД (локальное зеркало)

*Опционально, по умолчанию выключено.*

Когда задан `DATABASE_URL`, база данных стоит на критическом пути **каждого** запроса (auth-проверки читают настройки и проверяют API-ключи на каждый вызов). Если она становится недоступна, узел перестаёт обслуживать, а перезапуск контейнера посреди сбоя вообще не загрузится.

Включите **Settings → App settings → "Keep a local mirror of the database"** (или задайте `LLAMAMAN_DB_MIRROR=1`), и узел держит write-through копию в `DATA_DIR/db_mirror/`.

| Работает офлайн | Заблокировано офлайн |
|---|---|
| Весь инференс (оба порта) | Создание первого пользователя (`/setup`) — у совсем новой установки зеркала для отката всё равно нет |
| Запуск / остановка / сон / пробуждение моделей | |
| Загрузки, хэширование моделей и проверки обновлений | |
| Создание и редактирование **пресетов** (включая для моделей, которые вы только что скачали) | |
| Создание и отзыв **API-ключей** | |
| Изменение **настроек** загрузок и приложения | |
| Добавление и удаление **токенов Hugging Face** | |

Офлайн-изменения попадают в только-дописываемый журнал и проигрываются при переподключении (проба каждые 10 с). Журнал фиксирует *правку*, а не итоговую строку, поэтому изменение, сделанное другим узлом во время сбоя, выживает (другое поле пресета, другой ключ настроек, другой HF-токен остаются нетронутыми).

**Требования и оговорки:**

- **`DATA_DIR` должен быть персистентным томом** (в примерном compose-файле он уже такой).
- **Каждому узлу нужен свой `DATA_DIR`.** Зеркало помечается id узла-владельца; если два узла используют один каталог, зеркалирование просто выключается, а не портит оба представления.
- **Секреты попадают на локальный диск.** Настройки копируются дословно; **токены Hugging Face зеркалятся открытым текстом.** Пароли и API-ключи и так хранятся только в виде хэшей. Если вы выбрали MariaDB отчасти ради того, чтобы держать секреты подальше от отдельных хостов, именно этот компромисс — причина, почему функция opt-in.
- **Межузловая балансировка останавливается во время сбоя.** Сведения о доступности пиров хранятся в базе данных; деградировавший узел видит только себя.
- **Смены API-ключей локальны до переподключения.** Ключ, созданный офлайн, работает только на этом узле; ключ, **отозванный** офлайн, остаётся валидным на других узлах до переподключения. Планируйте отзывы соответственно.
- **Логи запросов отбрасываются, а не буферизуются,** пока узел офлайн (записи несут полные тела; копить их через долгий сбой — значит рисковать заполнить том).
- **Выключение зеркала посреди сбоя откладывается** до переподключения.
- Миграции схемы никогда не идут в деградированном состоянии; они выполняются против настоящей базы при переподключении, до любого проигрывания журнала.

<a id="environment-variables"></a>
## Переменные окружения

### Core

| Переменная | По умолчанию | Описание |
|---|---|---|
| `LLAMAMAN_NODE_NAME` | *(обязательна)* | **Обязательна.** Уникальная стабильная идентичность — ключ партиции хранимого состояния и кластерная идентичность. Любая строка; выберите один раз и не меняйте (изменение позже осиротит хранимое состояние). |
| `MODELS_DIR` | `/models` | Каталог, сканируемый на файлы моделей (путь в контейнере) |
| `DATA_DIR` | `/data` | Каталог для персистентной конфигурации/состояния (JSON-файлы) |
| `RECORDINGS_DIR` | `{DATA_DIR}/request_log` | Каталог записей request log по беседам. Только JSON-бэкенд; игнорируется при заданном `DATABASE_URL` |
| `LOGS_DIR` | `/tmp/llama-logs` | Каталог логов инстансов и загрузок (путь в контейнере) |
| `HOST_MODELS_DIR` | *(та же, что `MODELS_DIR`)* | **Хостовый** абсолютный путь тома моделей. Должен совпадать с левой стороной `-v /host/path:/models` — передаётся демону Docker при порождении контейнеров-соседей |
| `HOST_LOGS_DIR` | *(тот же, что `LOGS_DIR`)* | Хостовый абсолютный путь тома логов. То же требование, что у `HOST_MODELS_DIR` |
| `ARCHIVE_DIR` | *(не задана)* | Путь в контейнере, куда смонтирован архивный том (например `/archive`). Задание включает [Архив моделей](MODELS.md#model-archive); не задана — скрывает его |
| `PORT_RANGE_START` / `PORT_RANGE_END` | `8000` / `8020` | Пул публичных портов llama-server/прокси |
| `INTERNAL_PORT_RANGE_START` / `INTERNAL_PORT_RANGE_END` | `9000` / `9020` | Пул внутренних портов, используемый при включённом режиме прокси |
| `LLAMAMAN_PROXY_PORT` | `42069` | Порт Ollama-совместимого прокси |
| `LLAMAMAN_MAX_MODELS` | `0` | Максимум одновременных chat-моделей через прокси (LRU-вытеснение; 0 = безлимит). Правила: [Вытеснение моделей](MODELS.md#model-eviction) |
| `LLAMAMAN_IDLE_TIMEOUT` | `0` | Минуты idle-timeout для инстансов под управлением прокси (0 = отключено) |
| `LLAMAMAN_PDF_MAX_CONCURRENT` | `4` | Максимум одновременных растеризаций PDF на весь процесс. Каждая растеризация запускает poppler и занимает несколько сотен МБ временной RAM на высоких DPI |
| `SECRET_KEY` | *(авто)* | Flask-секрет сессии. При незаданном выводится из machine-id. Задайте для multi-replica развёртываний |
| `SESSION_COOKIE_NAME` | `llamaman_session` | Имя сессионной cookie. Пространство имён, чтобы llamaman уживался с другими Flask-приложениями на том же хосте — cookie скоупятся по host+path, а не по порту |
| `DATABASE_URL` | *(не задана)* | Строка подключения MariaDB/MySQL. Не задана = JSON-файлы |
| `LLAMAMAN_DB_MIRROR` | *(не задана)* | Принудительно включает (`1`) / выключает (`0`) локальное зеркало БД, переопределяя поузловую настройку. Осмысленно только с `DATABASE_URL` |
| `HEALTH_CHECK_TIMEOUT` | `3` | Таймаут в секундах health-проверок инстансов |
| `MODEL_LOAD_TIMEOUT` | `300` | Сколько секунд ждать, пока модель станет healthy. Поднимите для очень больших моделей |
| `REQUEST_TIMEOUT` | `300` | Таймаут **чтения** в секундах для исходящих запросов в llama-server, межузловой пересылки и ожиданий acquire гейта. **Не** регулирует время connect к пирам (отдельная граница в 5 с) |

<a id="clustering"></a>
### Кластеризация

Опционально. `LLAMAMAN_NODE_NAME` (в Core) заодно служит кластерной идентичностью и обязателен для всех установок.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `CLUSTER_ENABLED` | `false` | Задайте истинное, чтобы включить узел в кластер. Требует `CLUSTER_SECRET`; игнорируется с предупреждением, если секрет пуст |
| `CLUSTER_SECRET` | *(не задан)* | Общий bearer-токен (`X-Cluster-Secret`) для всего межузлового HTTP. Одинаковый на каждом узле. Используйте длинное случайное значение, по доверенной сети или за TLS |
| `CLUSTER_ADVERTISE_URL` | *(не задан)* | Как пиры обращаются к UI/API **этого** узла — hostname/IP, маршрутизируемый с других хостов (не `localhost`). Без него узел только для просмотра |
| `CLUSTER_NODE_ONLINE_WINDOW_S` | `45` | Секунды с последнего heartbeat, после которых узел показывается офлайн. Поднимите, если узлы флапают под нагрузкой или при расхождении часов |
| `LLAMAMAN_PERF_LOG` | *(выкл)* | Диагностика. Задайте истинное, чтобы логировать замеры по фазам (`perf <name> <ms>`) для подозреваемых медленных путей: удалённая остановка инстанса, кластерные прокси-пересылки, пробы достижимости, снимок heartbeat, auth-проверки, `save_state`, статистика контейнеров. По умолчанию выкл; ничтожные накладные расходы при выкл |
