# 集群

> **注意：** 本文为译文，可能落后于[英文版](../en/CLUSTERING.md)；以英文版为准。

*可选功能，默认关闭 —— 单节点部署完全不受影响。*

多个 llamaMan 部署可以作为**一个逻辑集群**协同工作：一个统一的仪表盘聚合每个节点的 GPU、实例和下载，支持跨节点启动/镜像拉取/下载以及多节点共享队列负载均衡。节点通过共享存储后端互相发现 —— 无需两两交换密钥。

**系统要求：**

- **共享存储后端** - 所有节点指向**同一个** `DATABASE_URL`（MariaDB/MySQL，参见 [Storage Backends](CONFIGURATION.md#storage-backends)）。JSON 存储是单机独立的，无法共享。
- **每个节点拥有唯一的 `LLAMAMAN_NODE_NAME`** - 每个节点的集群标识（而且任何安装方式本身都需要设置）。
- **每个节点使用相同的 `CLUSTER_SECRET`** - 用于所有节点间 HTTP 通信的 bearer token（作为 `X-Cluster-Secret` 发送）。
- **每个节点配置 `CLUSTER_ADVERTISE_URL`** 用于跨节点*操作* - 其他主机可路由访问的主机名/IP（不能是 `localhost`），例如 `http://srv1:5000`。未配置此项的节点会显示在仪表盘中，但处于只读状态。

在**每个**节点上配置（仅 `LLAMAMAN_NODE_NAME` 和 `CLUSTER_ADVERTISE_URL` 不同）：

```yaml
environment:
  - LLAMAMAN_NODE_NAME=srv1                 # unique per node
  - DATABASE_URL=mysql+pymysql://llamaman:pass@db-host:3306/llamaman   # identical
  - CLUSTER_ENABLED=true
  - CLUSTER_SECRET=a-long-shared-random-secret   # identical
  - CLUSTER_ADVERTISE_URL=http://srv1:5000  # this node's address, routable from peers
```

每个节点每隔约 5 秒发送一次心跳；沉默时间超过 `CLUSTER_NODE_ONLINE_WINDOW_S`（默认 45 秒）的节点将显示为离线。可在 **Settings → Cluster** 下查看与管理。

部分设置仅作用于单个节点，因为它们与具体主机绑定：跟踪的 **Docker 镜像**、模型上限逐出开关以及[负载下唤醒设置](#waking-under-load)。其余所有内容均在整个集群内共享。活跃的共享队列分组别名（shared-queue group aliases）会在 `/api/tags` 和 `/v1/models` 中作为可选模型发布（集群范围内去重），客户端发送别名即可将其路由至服务该模型且负载最低的节点。

**分组 context 长度为集群全局生效。** 无论客户端请求哪个节点，`/api/show` 和 `/v1/models` 报告的队列分组 context 均为**可接收流量的节点上所有活跃成员中的最小值（min）**。离线或仅查看节点上的成员不计入。包含不同 ctx 值成员的分组会对外宣告较小的值，从而确保按该大小构建的 prompt 可以安全分发到任何目标节点 —— 较大成员上的额外空间仅保持不用。即使节点本地没有该分组的成员，它仍能响应（`context_length` 从共享实例状态中的对等节点运行时 ctx 填充，或从共享 DB 中的预设行填充）；在任何地方都没有活跃成员的分组仍返回 404 / 无条目。当该成员的 ctx 超过宣告的最小值时，操作员 UI 上的实例卡片会添加 `ctx <min>, capped by <node/model>`，方便你查看是哪个对等节点拉低了整个分组。

> **安全性：** 集群密钥允许任何对等节点在此节点上执行操作。请在受信任的网络或 TLS 保护下运行节点间流量。

集群相关环境变量：[Clustering variables](CONFIGURATION.md#clustering)。

<a id="queue-groups"></a>
## 队列分组

队列分组将多个实例归入一个 **Queue group name** 之下，客户端可以将该名称发送到任意节点。下表显示了从另一节点的角度看每个成员的情况：

| 成员状态 | 是否列在 `/api/tags` 和 `/v1/models` 中 | 是否接收路由流量 |
|---|---|---|
| 健康（healthy） | 是 | 首选 |
| 启动中（加载中） | 是 | 排在健康成员之后 |
| 休眠 | 是 | 最后，且排在所有清醒成员（包括回退成员）之后。请求会将其唤醒。 |
| 正在停止或已停止 | 否 | 从不 |
| 位于没有 `CLUSTER_ADVERTISE_URL` 的节点（仅查看） | 否 | 从不 |
| 位于离线节点（45 秒无心跳） | 否 | 从不 |

**接收路由工作需要 `CLUSTER_ADVERTISE_URL`。** 没有它，节点仍可向对等节点发送请求，但任何对等节点都无法访问它。

**休眠和停止在这里含义不同。** 空闲超时会让实例进入休眠，休眠成员在流量需要时唤醒。已停止的成员会保持停止：操作员停止、逐出和崩溃都会进入该状态，来自其他节点的请求不会重启它。向持有它的节点请求会得到 `503`，除非该名称同时也是该成员自身的文件，此时仍会将其唤醒。

<a id="waking-under-load"></a>
### 负载下唤醒

清醒成员会将请求排队而不是拒绝，因此仅靠流量要等到整个队列溢出后才能到达休眠成员。因此 llamaMan 会提前唤醒一个。当分组内所有健康成员都已满、有请求在排队且没有正在加载的成员，并连续持续 3 次轮询（约 15 秒）时，会唤醒一个休眠成员。在整个集群中，只有持有休眠成员的节点中名称最小的节点会执行此操作，且每次轮询每个分组最多唤醒一个成员。主成员先于回退成员唤醒。

只有能增加容量的休眠成员才计入：它的 **Max Concurrent** 必须大于 `0`，且不能与同一节点上的清醒成员共享队列。

如果模型权重放不进节点的空闲显存，则跳过唤醒并记录一行日志。该检查会累加所有 GPU 的空闲显存，且只计算权重，因此通过检查的模型仍可能加载失败。如果无法读取显存，或模型没有可测量的文件（Strata 的虚拟模型），则照常唤醒。

两项设置都是节点级的，通过 `POST /api/settings` 配置：

| 设置 | 默认值 | 含义 |
|---|---|---|
| `eager_wake_enabled` | `true` | 此节点是否在负载下唤醒其休眠成员 |
| `eager_wake_polls` | `3` | 唤醒前连续饱和的轮询次数（每次 5 秒） |

<a id="when-a-group-cant-be-served"></a>
### 分组无法提供服务时

如果其他节点托管该分组，但没有节点能接受请求，客户端会收到列出每个节点及原因的错误，而不是 "model not found"：

| 状态码 | 错误码（OpenAI 路由） | 含义 |
|---|---|---|
| `429` | `group_full` | 至少一个对等节点的队列已满。重试可能成功。 |
| `503` | `group_unavailable` | 对等节点离线、仅查看、无法访问或未就绪。 |

所属节点会为其自身成员返回以下 `503` 错误码，入口节点收到后会尝试下一个成员：

| 错误码 | 含义 |
|---|---|
| `model_stopping` | 该成员正在关闭 |
| `group_stopped` | 本节点上的所有成员都已停止 |
| `wake_failed` | 唤醒失败 |
| `wake_timeout` | 该成员未能及时变为 healthy |

分组名称不会启动名称仅包含它的本地文件。名称完全相同的文件仍会运行。

<a id="troubleshooting-a-group-that-isnt-visible"></a>
### 分组不可见的排查

- **JSON 后端需要一个共享的 `DATA_DIR`。** 节点通过注册表相互发现，因此目录各自独立意味着每个节点都看不到对等节点。除非目录确实共享，否则请使用 MariaDB。
- **降级的数据库会有意隐藏对等节点。** 当 DB 镜像提供读取时，节点只能看到自己并在本地提供服务。
- **负载探测失败不会隐藏分组。** 未响应的对等节点依据其快照（最多 45 秒前）仍可路由，但排在所有已响应的对等节点之后。日志会记录对某对等节点的探测何时开始失败以及何时恢复。
